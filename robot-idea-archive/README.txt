本机启动
双击“启动档案.command”。第一次需要输入新的网站访问密码，账号 admin。
已有账号不会被启动脚本重置。密码只在 data/archive.sqlite3 内存为不可逆校验值。
在 http://127.0.0.1:5187/ 打开，只监听本机。终端 Ctrl+C 停止。
运行环境在 .venv；打包交付不含 .venv，需要在新电脑安装 Python 3.10+ 后重新安装依赖。
已安装当前环境可以直接运行：.venv/bin/python -m unittest -v test_app.py

Ubuntu 部署（仅在该实例恢复、完成只读环境检查后执行）
1. 以 SSH 验证确实是 #29473，固定 SSH 主机公钥。不要把 103.236.89.42 的 22 端口当作本实例。
2. 检查 /etc/os-release、python3 版本、ss -lntp、磁盘空间及已有服务。
3. 上传本包到单独临时目录，查看 deploy/install.sh 的固定动作。
4. 若符合 Ubuntu / systemd 条件且端口 5187 空闲，在解压后的目录运行 sudo bash deploy/install.sh。
   安装器遇到已有同名安装会停止，避免覆盖。它只添加独立应用目录、服务用户和 systemd 服务。
5. 在终端设置新的网站密码，账号 admin；不复用服务器 root 密码。
6. 本机 curl http://127.0.0.1:5187/healthz 检查；验证未登录 /api/ideas 返回 401。
7. 服务商 NAT 面板需要另加一个 TCP 网站映射：外部端口按面板可用值 → 实例内部 5187。
   该映射会使登录页在公网可访问，属于后续需要明确确认的网络暴露步骤，目前未创建。
   原 SSH 32905 → 22 不变。浏览器地址应使用网站映射端口，不能用 SSH 的 32905 打开网站。
8. 通过公网地址测试登录、新建、照片上传、评分、刷新及导出；重启应用服务后确认记录仍在。

访问与 HTTPS
当前实现可按 IP + NAT 端口运行 HTTP；HTTP 不加密密码和内容，公网正式使用前应安排 HTTPS。
有域名及对应转发后可由可信证书与反向代理提供 HTTPS，并设置 ARCHIVE_HTTPS=1。
尚未配置域名、TLS 或公开网站映射；不能把本地功能通过描述成线上部署成功。

数据与备份
应用：/opt/robot-idea-archive；数据：/var/lib/robot-idea-archive。
systemctl status robot-idea-archive
journalctl -u robot-idea-archive -n 80
网页的“导出备份”包含 ideas.json + media/ + models/；用于保存或迁移记录，当前没有网页导入功能。
deploy/backup.py 额外支持 SQLite 一致性快照及全部照片，可用于完整恢复。
备份命令：sudo -u robotarchive /opt/robot-idea-archive/.venv/bin/python /opt/robot-idea-archive/deploy/backup.py
恢复：先停止本应用，保留原 data 目录快照，再恢复 archive.sqlite3、uploads/ 与 model_files/ 到新的空数据目录，不恢复旧 session.key。
重新启动会生成新会话密钥，已登录设备需重新登录；账号密码校验值保留。
更新：先备份数据，保留 session.key；单独替换 app.py/static/ 等代码，安装依赖，再重启本应用。
初始 seed 只添加缺少的固定方案，不覆盖现有编辑内容。备份 ZIP 中不含服务器认证信息。
