# 📚 阶段五：跨芯片双向串口通信协议引擎与回环压测

> **阶段目标**：掌握单片机高速异步串行通信（UART）驱动机制，构建基于有限状态机（FSM）的流式解包与累加校验和引擎，通过硬件自回环（Hardware Loopback）实现 0 丢包闭环验证。

---

## 1. ESP32-S3 全引脚矩阵映射 (GPIO Matrix)

与传统单片机固定引脚不同，ESP32-S3 拥有 **GPIO Matrix（通用引脚完全矩阵映射）** 特性：
- 任何数字硬件外设（UART、I2S、I2C、PWM）均可任意路由至任意空闲引脚。
- **本工程引脚映射**：
  - **UART2 发送端 (TX)** ➔ `GPIO 1`
  - **UART2 接收端 (RX)** ➔ `GPIO 2`
  - 彻底避开了板载 USB/JTAG 下载调试口（GPIO 43/44），杜绝信号串扰。

## 2. 串口底层驱动与 512 字节环形接收队列 (Ring Buffer)

### 2.1 为什么单片机串口必须配置中断环形队列？
- 在 115200 波特率下，字节以每 **86 微秒** 一个的高速持续到达。
- 若 CPU 忙于渲染 OLED 屏幕（耗时数毫秒），直接读寄存器会产生 **硬件 FIFO 溢出丢包**。
- **企业级做法**：通过 `uart_driver_install` 开辟 **512 字节中断接收环形队列**。底层硬件中断自动接收入队，应用层随时非阻塞批量提取，**彻底实现物理层 0 丢包！**

---

## 3. 流式通信的痛点与有限状态机 (FSM) 解密

### 3.1 串口字节流的三大通信陷阱
1. **断包**：一包 10 字节数据被中断切开，分两次到达；
2. **粘包**：一次性读到 25 字节（包含多包完整数据 + 1 包残缺数据）；
3. **电磁杂波**：总线干扰产生随机孤立错误字节。

### 3.2 有限状态机自愈机制
```text
  [等待帧头 0xAA / 0x55] ──收到有效帧头──► [读取指定长度载荷数据] 
           ▲                                       │
           │                                   收齐载荷字节
           │                                       │
           └─── 校验失败/解析完成 ◄─── [16-bit 累加校验和验证]
```
- 逐字节将数据流喂入状态机；
- 遇到错误或干扰字节自动丢弃并重置，**毫秒级自愈找回帧头**，确保业务层收到的每一包数据绝对合法。

## 4. 双向通信协议数据帧规范

```c
#pragma pack(push, 1) // 1 字节严格对齐

// 1. 控制帧 (大脑 -> 底盘, 0xAA, 9 字节)
typedef struct {
    uint8_t  header;        // 0xAA
    uint8_t  cmd_id;        // 指令计数器
    int16_t  target_speed;  // 目标线速度 (mm/s)
    int16_t  target_yaw;    // 目标角速度 (mrad/s)
    uint8_t  motion_mode;   // 运行模式 (0:待机, 1:平衡, 2:急停)
    uint16_t checksum;      // 16位累加校验和
} RobotCmdPacket_t;

// 2. 遥测状态帧 (底盘 -> 大脑, 0x55, 13 字节)
typedef struct {
    uint8_t  header;        // 0x55
    uint8_t  state_id;      // 状态计数器
    float    pitch_angle;   // 实时俯仰角 (度)
    int16_t  actual_speed;  // 实际车速 (mm/s)
    uint16_t battery_mv;    // 电池电压 (mV)
    uint8_t  status_flags;  // 状态标志 (平衡/跌倒/低电)
    uint16_t checksum;      // 16位累加校验和
} RobotStatePacket_t;

#pragma pack(pop)
```

## 5. 硬件自回环压测实测数据与分析

### 5.1 实测指标
- **压测方式**：杜邦线物理短接 `GPIO 1 (TX)` 与 `GPIO 2 (RX)`；
- **传输速率**：~38 ~ 50 帧/秒 高频全双工通信；
- **丢包率**：**`0.00%`**；
- **协议校验通过率**：**`100%`**。

### 5.2 帧率机制解析
- 当调用 `s_uart.read(..., timeout_ms=5)` 时，带 5ms 超时机制与 20ms 延时叠加，循环频率约为 $38$ 帧/s；
- 将读取超时改为 `0`（纯非阻塞），通信频率即可严格精准锁定在 **$50.00$ 帧/s**。
