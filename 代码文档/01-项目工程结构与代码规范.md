## 2. ⚡ Zed 编辑器配置规范

项目根目录下已配置 `.zed/settings.json`，核心行为如下：

1. **自动保存 (Autosave)**：
   - 配置为 `after_delay`（延迟 1000ms 自动保存），防止意外断电或手滑丢失代码。
2. **保存时自动格式化 (Format on Save)**：
   - C / C++ 源码文件在保存时自动调用 `.clang-format` 执行格式化。
   - 保持 4 空格缩进，禁止使用 Hard Tab。
   - 自动移除行尾多余空格 (`remove_trailing_whitespace_on_save: true`)。
   - 文件末尾自动确保保留一个换行符 (`ensure_final_newline_on_save: true`)。

## 3. 📝 C / C++ 代码编码规范

### 3.1 命名规范
- **类名 / 结构体**：驼峰大写，如 `FaceEngine`、`RobotCmdPacket_t`。
- **函数名 / 方法名**：
  - C++ (ESP32)：小驼峰，如 `updateExpression()`、`recordAudio()`。
  - C (STM32)：下划线分词 + 模块前缀，如 `bsp_motor_set_speed()`、`kalman_update()`。
- **宏定义 / 常量**：全大写下划线，如 `PROTOCOL_FRAME_HEADER_CMD`、`I2S_SAMPLE_RATE_16K`。
- **成员变量 / 本地变量**：
  - C++ 类成员变量：前缀 `m_` 或后置下划线，如 `m_currentEmotion`。
  - 普通局部变量：小驼峰或下划线，保持简洁清晰。

### 3.2 内存与并发规范
- **ESP32-S3 (C++)**：
  - 大缓冲区（如音频流、动态位图、大模型响应包）优先使用 `heap_caps_malloc(size, MALLOC_CAP_SPIRAM)` 分配至 **8MB PSRAM**，严禁占用内部有限的 SRAM。
  - FreeRTOS 任务使用 `xTaskCreatePinnedToCore` 明确绑定 CPU 核心（Core 0 跑网络/音频，Core 1 跑 UI/控制）。
- **STM32G473 (C)**：
  - 严禁在中断服务函数 (ISR) 中进行任何耗时的阻塞等待（如 `HAL_Delay`）或大内存拷贝。
  - 高频控制（PWM 修改、编码器读取）必须使用 LL 库内联函数，保证微秒级执行。

## 4. 🔨 编译与构建命令

在终端中进入对应工程目录后，直接执行全局别名快捷命令：

```bash
# 编译 ESP32-S3 大脑工程
cd firmware_brain
esp-build

# 编译 STM32 底盘主控工程
cd firmware_chassis
stm32-build
```
