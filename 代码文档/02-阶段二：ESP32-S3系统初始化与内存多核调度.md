# 📚 阶段二：ESP32-S3 硬件自检、内存体系与多核调度机制

> **阶段目标**：掌握 ESP32-S3 双核架构分工，理解 16MB Flash 与 8MB Octal PSRAM 内存层次，建立 FreeRTOS 多任务调度模型与串口调试规范。

---

## 1. 双核 Xtensa LX7 处理器分工架构

ESP32-S3 搭载两颗最高主频 240MHz 的 32 位 Xtensa 双核 CPU，我们采取**系统核与控制核明确分离**的架构策略：

```text
┌──────────────────────────────────────┐  ┌──────────────────────────────────────┐
│          CPU Core 0 (系统核)          │  │          CPU Core 1 (控制核)          │
├──────────────────────────────────────┤  ├──────────────────────────────────────┤
│ • Wi-Fi / 蓝牙无线协议栈             │  │ • OLED 拟人表情渲染动画 (33 FPS)     │
│ • I2S 音频流 DMA 中断传输            │  │ • 离线姿态解算与运动学状态机         │
│ • 网络通信与音频解码任务             │  │ • STM32 底盘串口双向高速通信任务     │
└──────────────────────────────────────┘  └──────────────────────────────────────┘
```

- **核心价值**：防止高耗时的 UI 渲染或姿态计算阻塞底层的无线与音频 DMA 中断，实现真正的硬实时并发。

## 2. FreeRTOS 任务核绑定 (`xTaskCreatePinnedToCore`)

在多核实时操作系统中，我们使用 `xTaskCreatePinnedToCore` 将任务精准绑定至指定核心：

```cpp
xTaskCreatePinnedToCore(
    oledRenderTask,   // 任务入口函数指针
    "oled_task",      // 任务名称 (调试使用)
    4096,             // 独立任务栈空间大小 (4096 字节)
    nullptr,          // 传递给任务的参数
    5,                // 任务优先级 (1~25，数值越大优先级越高)
    nullptr,          // 任务句柄
    1                 // 关键！明确绑定到 CPU Core 1
);
```

### 💡 核心概念讲解：
- **任务栈空间**：每个 FreeRTOS 任务拥有自己独立的栈，局部变量和函数调用深度均消耗栈内存。
- **`vTaskDelay`**：基于系统嘀嗒定时器（Tick）的非阻塞延时，延时期间 CPU 会主动让出给同核的其他就绪任务，绝不空转浪费电量。

## 3. 16MB Flash 与 8MB Octal PSRAM 内存体系

ESP32-S3-N16R8 拥有卓越的内存配置：

| 存储介质 | 物理容量 | 总线类型 | 作用定位 |
| :--- | :--- | :--- | :--- |
| **内部 SRAM** | ~380 KB | 内部高速总线 | 极速运行中断服务程序 (ISR) 与 DMA 发送接收缓冲区 |
| **外部 PSRAM** | 8 MB (8192 KB) | 8线 Octal OPI 高速接口 | 存放语音大模型 (WakeNet)、全双工音频流、视觉图像缓冲 |
| **外部 Flash** | 16 MB | 4线 QSPI / DIO 接口 | 固件镜像、OTA 双分区备份、静态资源字库存储 |

- **自检实测**：系统启动后，总可用空闲堆内存高达 **8.77 MB**（8772299 字节），为后续端侧 AI 语音交互打下了坚实基础。

## 4. 串口时钟采样机制与 Resource Busy 排查规范

### 4.1 波特率采样时钟原理
- 串口通信（UART）基于波特率（115200 bps）传输数据，单片机与电脑内部各自运行着独立的定时采样时钟。
- **排错经验**：若波特率多输了一个 0（设为 1152000），电脑端采样时钟频率是单片机的 10 倍，导致相位严重错位，读取到的信号全部变成 `0x00` 或乱码。

### 4.2 操作系统串口独占机制
- 串口硬件在 macOS/Linux 底层属于**独占设备文件**（`/dev/cu.usbserial-1140`）。
- **标准操作流**：当 VOFA+ 打开串口监视数据时，串口通道被 VOFA+ 锁定；烧录固件（`esp-flash`）前必须先在 VOFA+ 中**断开连接**，烧录完成后再重新连接，避免触发 `[Errno 16] Resource busy`。
